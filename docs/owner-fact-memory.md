# Owner 长期记忆（owner_fact_v1）使用说明

首批范围：**主人 QQ 私聊 + 眼镜（同 owner 授权空间 owner-working）**。
群聊、其他成员、Web/API 控制台聊天**不自动采集**；控制台/CLI 提供受鉴权
的管理入口（查看、删除、治理）。宿主启动日志必有明确一行装配状态
（on / off / 未装配+原因 / 装配失败+原因），不存在静默跳过。

## 它记什么、怎么记

- 只记**你明确自述**的原话（如「我养的猫叫年糕」），逐字保留 quote 与
  来源消息 ID（evidence_id）；模型推断、假设句、疑问句、反讽、转述他人、
  助手自己的话不入长期记忆。
- 记忆状态是 **asserted（有证据支持的用户自述）**，不是 verified——它
  表示「你说过」，不表示现实世界核实为真，也不等于永久有效或可任意分享。
- 采集发生在回复生成之前的快速受理（不拖慢回话），提炼在后台单 worker
  完成；队列有界（全局 128 / 单 owner 64），满了拒新不丢旧、不影响聊天。
- 敏感内容策略边界（启发式，**不是完整 DLP，不做「绝不泄漏」承诺**）：
  手机号/证件号/银行卡号（正则）与住址、凭据类词表命中即**整条放弃**
  （不降级保存）。已知限制：「住在/家住」等城市级自述也会被整条拒绝
  ——宁可漏记，不做部分保存。请不要在对话中输入不希望被记住的敏感信息。
- 渠道凭据前置拦截：sudo 口令类消息在渠道层先于记忆/历史/日志被截获
  验证，不进入采集链路（工程纪律，非全量内容过滤承诺）。
- 授权（配对绑定、空间暂停开关）在**写入与提交时实时复查**：解绑、暂停
  之后，在途任务提交会被拒绝并清掉证据原文。

## 怎么召回

聊天时自动注入「长期记忆（用户自述）：…」片段，与既有 curated/情节记忆
共享统一预算：**最多 8 条、单条 ≤300 字符、总量 ≤2400 字符**。QQ 与眼镜
是同一 owner 空间：QQ 说过的猫名，眼镜问「我的猫叫什么」也能答。
只有 accepted 且未过期的事实参与召回；pending/superseded/expired/deleted
一律不出现。

## 怎么更正

直接在聊天里自然更正（「名字说错了，它叫团子」）：提炼管道识别对同一
谓词的明确矛盾后，旧事实标 superseded 退出召回，新事实带双向版本链接替。
歧义不覆盖（「今天去北京出差」不会动「住上海」）；拿不准只挂 pending，
不进召回。

## 怎么删除（遗忘）

- 聊天：`忘掉：<完整内容>`。只做确定性精确匹配；「忘掉那个」这类模糊
  线索**不会**删任何东西（会提示说全）。删除后：
  - 事实记录变为无正文墓碑，任何迟到任务、重试、重启、旧备份导入都不能
    复活；
  - **登记过的 owner 会话**（来源绑定索引内）：短历史整清，chat 情节
    **整条删除**——不依赖词面匹配，助手改写/echo（即使不含原名）也无法
    经情节召回复述。注意这会清掉这些会话的本地聊天记忆（包括同会话
    无关轮次），是保守取舍；清理的是**本地记忆**，不是撤回已发送的
    QQ/平台消息；
  - 未登记会话、群、他人数据、其他结构化事实一律不碰；
  - 同一证据重放被拒；之后你**重新主动说**同一事实算新证据，可以再记。
- 正文清理与水位保留的边界：遗忘立即清掉证据原文/quote/事实正文；
  **无正文**的水位元数据（证据墓碑、终态任务记录，journal 上限 256 条
  滚动）长期保留——它们只是防复活栅栏与审计计数，不含可复述内容。
- API：`DELETE /api/v1/memory/{offact:...}`（走领域 forget，含上述抑制）；
  Studio 旧治理入口对该命名空间一律 409 拒绝直写。
- 导出/导入：JSONL 导出含该数据（备份视角），但**导入不支持此命名空间**
  ——JSONL 不是生命周期恢复手段（不含墓碑/水位账本），完整恢复只认整库
  SQLite 备份。

## 开关与配置

| 项 | 默认 | 说明 |
| --- | --- | --- |
| `WHALE_OWNER_FACT_MEMORY=0` | 开启 | 紧急开关：关闭后不采集、不召回，启动日志明示 off |
| `WHALE_OWNER_FACT_MODEL_TIMEOUT_S` | 20 | 提炼模型单次超时秒数；按所用供应商/模型的实际时延调整（参考：首轮真实评测正常候选最长 13s） |
| 空间级「停止记录」 | 关 | Studio memory/pause：暂停该空间采集与提交 |
| worker | 单宿主单实例 | 随宿主启动/关闭（server stop、REPL 退出、settings 换装都停旧 worker）；多宿主共库时靠 lease+CAS 串行，不双消费 |

## 测试层次与保证范围（如实）

- **系统集成测试**（tests/integration/test_owner_fact_entry.py，24 例）：
  使用**确定性 Fake 提炼输出**（固定测试）验证装配、真实来源鉴权、遗忘
  闭环、预算、窄分派等系统链路——它不衡量模型语义质量；
- **真实模型小样本评测**（固定 case 集，非本仓文件，报告在内部总 docs）：
  首轮 20 条人工合成（10 正 / 10 负）未过门 → 修正提炼纪律后第二轮
  20/20（TP10 / FP0 / FN0 / TN10），另有 4 次真实 worker 全链路调用通过
  （含自然更正、重启、forget 后旧证据重放拒绝）。**小样本结果不构成总体
  精度保证**；两类分数不混用；
- 规划的 60 条人工标注正负集 + 30 个长间隔查询**尚未完成**（见下「已知
  事项」），上线候选阈值（precision≥95% 等）在该集合完成前不宣称达成；
- 安全门（越权/助手晋升/删除复活/过期现状/预算违规）要求恒为 0 失败。

## 已知事项（首批如实边界）

- 60+30 质量评测集与 observe p95≤20ms 的自动化性能断言尚未落地（性能
  基线现由 evals/memory_bench 覆盖检索开销，不含本管道时延门）。
- 遗忘会整清登记会话的本地聊天记忆（保守取舍，见上）；平台侧已发送
  消息不受影响、不可撤回。
- 控制台（API/CLI）聊天入口不采集；其管理入口经 console 来源窄鉴权，
  未登记该来源的部署上管理操作会被拒绝（fail closed）。
