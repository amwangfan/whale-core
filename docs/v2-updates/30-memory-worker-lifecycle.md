# 第30轮：记忆队列、租约与关闭恢复

## 行为与兼容

普通Worker.stop保留已有的“停止领取，让在途任务完成”语义，更正任务仍可等待前一事实提交。新增quiesce用于宿主关闭/重载：与领取、快照读取及结果提交共用生命周期锁，先停止领取并把仍属于自己的活动租约CAS退回pending，不增加失败/重试次数；再有界等待线程。迟到模型结果不再访问原存储或提交事实，可由新worker继续处理该持久任务。重复quiesce不再访问已关闭的原存储。

OwnerFactStack默认shutdown使用quiesce。显式drain时先给在途任务完成的机会，等待后仍会执行静止化，避免超时返回后写入已关闭的库。关闭外部模型线程本身仍不受Python安全强杀，不能把“完成存储隔离”说成“外部模型调用已结束”。quiesce返回线程是否真正退出，不谎称已排空队列。

start加锁防并发创建两个线程；停止后的实例不可重新启动，应构造新实例。stop的join与在途等待共享一个截止时间，不再各等待一份timeout，也不join当前线程。

## 租约与积压

缺失、损坏、错误类型、无时区的租约均可恢复，避免长期挡住同owner/space的后续任务。有效租约、domain顺序与worker/token CAS保护保留。容量评估确认已有全局128和单owner64的默认上限，本轮没有增加新容量开关或放宽既有上限。
