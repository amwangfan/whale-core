# 第45轮：探索调度服务代次与取消

工作流调度器为每次装配维护独立代次和取消事件。set_service取消旧事件并重置新服务的调度、结果和退避状态；旧探索完成/失败后必须同时匹配服务、代次和取消状态才能更新或持久化调度统计。统计写入与代次检查在同一锁内，服务替换返回后不会再发起旧代次的worker统计写入。

同一worker的tick不重叠，避免同时到期重复启动探索。stop与start协调，停止时取消当前代次并清空下一次时间，仍保留最多3秒的原有线程等待；重新启动用新取消事件，启用/替换后的首次tick仍等待完整间隔。status增加in_flight，明确旧调用是否尚在自然结束。

探索服务在入口、执行锁等待后、工具返回后及草稿生成前检查取消；检查顺序先看事件，避免取消已被观察到后仍读取旧设置/工具回执。调度统计写失败以last_persist_error记录异常类型，不把成功探索误记为模型错误或重复写入；不记录异常正文。

这仍是协作式取消。已进入的工具、存储操作或草稿生成步骤可能自然完成，不能撤销它们的实际副作用；没有宣称旧运行时/所有存储访问都被强制隔离。探索仍只生成草稿，不主动发送消息，手工工作流和审批语义不变。
