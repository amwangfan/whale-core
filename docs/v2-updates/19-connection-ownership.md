# 第 19 轮：重连与会话归属

Core 在 hello_ack 发送成功后才发布在线会话，发送失败时保留旧连接。成功替换立即收束旧连接自己的等待项，查询、动作和设备确认的响应同时核对连接归属。旧连接不能领取新连接的等待项；合法迟到动作回执仍按原动作索引持久化，供后续只读对账。

未知消息类型继续支持前向兼容，但仍必须遵守共同信封和 uplink 方向。缺少共同信封的局部契约目录在加载时失败，避免绕过基础校验。

Mobile 为每次 WebSocket 建连创建独立回调代次。旧连接迟到的打开、消息、失败或关闭回调不会影响新连接；主动断开及销毁清理代次、定时任务和分发器连接状态。销毁后的 OkHttp 回调安全丢弃，不再提交到已关闭的执行器。

新增实际 WebSocket 回环测试，验证失败重连保留旧会话、上线通知不能抢在 hello_ack 前发送；同步测试覆盖跨连接查询/动作/确认、旧帧与未知类型边界。Mobile 纯 JVM 总计 **120 项通过**，包括回调排队与连接替换策略；它不包含 Android WebSocket 客户端的完整组件构建。

最终全量与交付验证见[更新索引](README.md)。本轮不修改用户地址、模型、令牌或正在运行的服务。
