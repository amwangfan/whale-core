# 第50轮：聊天围栏起始识别收紧（PR#89 审查修复）

修复第46轮引入的回归：波浪线围栏 opener 原先在任意位置接受 `~{3,}`，普通聊天语气符（如「好呀~~~」）被误认成代码围栏，且未闭合时把剩余全文当代码保护，导致分气泡、`[[稍后补充:…]]`/`[[表情:…]]` 标记剥离、媒体引用净化（OSS 链接/本地产物 → `[图片]`）和群聊长度软裁整段失效。

审查最小输入（`plan_reply(..., is_group=True, max_segments=3)`）：

```text
好呀~~~ ◆ 另外一件事 [[稍后补充:待会]] https://demo.oss-cn-test.aliyuncs.com/demo.png
```

## 新起始规则

- **波浪线 opener 只认物理行首**：允许 0–3 个空格缩进（`^` 多行锚定，4 空格及以上缩进不认）。行中出现的 `~~~`/`~~~~`（包括 `◆` 后同行）一律是普通文本，不再保留同行的特殊围栏支持——这正是语气符误判的根因。
- **反引号 opener 保持原兼容**：仍可在说明文字或内联规划标记（如 `◆ `）之后同行出现，既有模型输出形态不受影响。
- 围栏字符与长度取自捕获到的真实 run，不含前导缩进空格；闭合规则不变——同种字符、长度不短于 opener、独占一行（允许 `\r` 结尾）；较短的内层行不闭合外层；未闭合保守保护到回复末尾。
- `has_code_fence` 与 `fenced_parts` 共用同一 `_OPEN_FENCE_RE`，软裁/分段/标记处理不会再出现「识别不一致仍误跳」。

这是收紧起始识别，不是完整 Markdown 解析器，也没有删除波浪线围栏支持：行首真实围栏（闭合/未闭合、带 info、0–3 空格缩进、长围栏、CRLF、多块）全部照常保护。
