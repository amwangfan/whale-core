# 第48轮：通知历史与已读操作的事务一致性

开工已拉取Core和Mobile上游，仍为`fdc895c`、`b0cf83a`，无新增。

通知历史的添加、标记单条已读、全部已读原先是独立读写，多个历史实例或SQLite连接同时操作时会丢通知或覆盖用户已读操作。现将各操作的读取、合并和保存放入底层MemoryStore事务，兼容内存和SQLite后端。

同一notification_id、同一event_id重复入库保留显式已读；新event_id替换同一通知时仍作为新内容设为未读。展示回执依旧不等于用户已读。历史容量只接受正整数，避免布尔值或小数被隐式转换成错误上限。

新增16项检查，修复前14项失败、2项通过；覆盖强制同快照并发读、添加与已读竞争、全部已读计数、SQLite双连接添加、重复事件和容量边界。通知链路合计98项通过。

这保证单次历史操作的事务一致性，不把整个notify流程和历史、队列、台账合成跨模块事务。排序仍按最新入库在前，容量保留既有截断语义。最终联合全量验证见第49轮。

没有修改Mobile、协议、网页、实际配置，也没有部署或重启。
