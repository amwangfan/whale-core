# 第31轮：动作存储清理与诊断

## 存储层

新增可选scan_keys(prefix, after, limit)，KV和record键统一排序、去重、限制返回量。SQLite按两个表的主键范围查询，每表先LIMIT再合并，不用LIKE，百分号/下划线是普通前缀字符。InMemory以小堆保留有限结果，仍需遍历内存键，不声称它具备磁盘索引复杂度。旧keys接口不变；第三方后端无scan_keys时可兼容回退，诊断scan_mode明确区分native/compat。

## 清理层

ActionRecords.sweep增加可选max_scan及两个游标。动作和回执各自最多检查max_scan条，另取一条判断是否还有后续；仍在事务中重读并维护索引/历史，遵守每批逻辑删除上限。游标前进、周期完成后回到开头；新插入到游标前方的键下一周期处理。它不是一致性快照，也不保证单次清理完成全库。

原手动调用不指定max_scan时保留完整扫描和原统计返回形状。后台改为每类500条，积压存在时下一心跳扫描继续，不再等一小时才处理下一批。完成周期后回到每小时触发；存储异常保留游标但退回小时级重试，避免故障时高频扫描。游标仅存当前网关内存，重启从头恢复，不新增业务数据库游标记录。

## 排障

已鉴权GET /api/v1/devices增加retention对象：state、at、duration_ms，以及检查/删除/标记数量、是否仍有后续、scan_mode。错误仅返回异常类型，不输出载荷或异常正文；不暴露扫描游标/原记录键。返回快照不会修改内部状态。本轮没有网页展示改动，可通过管理API查看。
