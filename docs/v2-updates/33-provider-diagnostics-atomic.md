# 第33轮：并发调用统计与诊断查询

模型请求在事务之外执行，完成后才在存储事务中重新读取、累加并保存计数。多个包装器、SQLite不同连接的重叠调用不会覆盖彼此的完成记录；失败分类和延迟样本一起提交，沿用现有字段与脱敏约定。

健康报告使用已有前缀扫描接口，每页500个键；SQLite不再先加载全部业务键。旧后端的报告仍兼容keys接口。完整报告仍返回全部供应商，因此总体内存随供应商数增长；内存后端的前缀扫描仍需遍历内存键，不宣称所有后端查询都变成常量时间。

拒绝非有限延迟累计值，过滤非有限样本及非法事件时间，避免JSON输出与分位数计算崩溃。损坏累计值沿用整体归零的既有策略。

验证：诊断相关23项通过；新增用12个同时进入模型的调用验证未锁住模型I/O，覆盖成功与失败并发、SQLite独立连接、1005个供应商跨页及旧后端兼容。最终全量结果见第34轮交付记录。
