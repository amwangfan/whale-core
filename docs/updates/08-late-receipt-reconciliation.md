# 第 08 批：迟到回执与超时对账

日期：2026-11-07。状态：联合验证完成，本次最后一轮。

实现提交：[6913326](https://github.com/dreaminutes/whale-core/commit/6913326)。

## 修复

- 清理任务将超期动作标为 `unknown` 时记录 `outcome_source=retention_timeout`，明确这是本地超时推定，不是设备确认。
- 原动作在保留窗口内收到真实终态回执后，可补齐该推定状态，持久化结果并标明 `device_receipt`；无需重发动作。
- 真实设备确认的第一个终态仍然优先；包括设备明确返回的 `unknown`，后续冲突回包不能覆盖。
- 中间态 received/accepted 不会把超时推定重新改成“进行中”。
- 清理与回执按同一记录互斥，防止旧快照覆盖已经落库的真实结果；不把整趟清理锁成一个长临界区。
- 回执的反向索引、动作记录与回执流水在同一临界区检查，避免清理后重新写出孤儿流水。
- 等待请求和后续状态查询使用同一个已确认结果，不因竞争返回矛盾状态。
