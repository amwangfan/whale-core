# 非 Windows 可用性补全计划

基线：main a53c707。用户目标：先规划，再全面修复并完成剩余目标，最终能正常使用，同时美化网页操作界面。Windows 桌面端不在本轮范围。生产部署和真实账号发送不在本轮自动执行范围。

## 当前证据

- 已有 Python 对话、SQLite 记忆、意图、插件、语音和媒体契约、主动行为、QQ/WeQ runner，以及 React 管理台。
- 基线 pytest：807 passed / 1 failed，失败为受限 root 容器内 Shell 降权 preexec 异常。
- profiles 直接注册 provider，但 PluginManager 未接管内置注册，导致控制台插件清单/启停与实际能力脱节。
- config.json 模型字段未被运行装配消费；没有完整网页设置/模型连接测试入口。
- 任务仅保存终态；取消、待批动作恢复、工具总时限存在缺口。
- 语音和媒体未统一挂载到标准运行入口，视频缺少真实 provider；产物无法在控制台安全访问。
- 控制台隐藏页全部挂载、token存在即视为连接，缺少完整错误/空态/移动端布局。

## 实施阶段

1. 配置组合根与插件生命周期：持久设置、私密凭据、热切换、统一内置清单、禁用立即撤销能力、CLI与API共用装配。
2. 运行时可靠性：任务持久化、期限/轮数、取消、exact-action审批和恢复、防止重复派发。
3. 官方能力：ASR/TTS/生图接线、真实异步视频、受鉴权产物、实时语音桥；缺凭据诚实不可用。
4. 控制台：连接验证、侧栏/移动端、总览、对话、插件配置、记忆、任务/审批/日志、设置与诊断。
5. 运行安全：Shell 系统沙箱/资源边界，API输入/来源/连接限制、记忆访问边界、密钥保护。
6. 发行验证：Linux容器/非Windows安装路径、备份恢复、wheel静态资源、文档与CI。

## 分工与接口

主代理负责 profiles/configuration/API/CLI 与最终集成；子代理分别负责 web、语音媒体、runtime/memory、独立安全审查及Shell。共享接口先约定，文件所有权不交叉。遵循仓库 AI_DEVELOPMENT_GUIDE 的推荐协作方式。

## 验收

- Python单元/集成与负向回归全部通过；前端测试、类型检查、生产构建通过。
- 干净安装可启动API并加载控制台；设置持久化后真实兼容协议服务可多轮对话。
- 插件禁用后不能继续使用缓存provider/tool；审批状态不等于已执行，恢复不会重复成功动作。
- 缺密钥/依赖/设备有可操作诊断；不静默降级mock；密钥不回传、不进SQLite/普通日志。
- 导出/删除/恢复与持久化一致；任务状态、工具回执和产物链接可核验。
- 无可用OS沙箱时Shell默认拒绝执行，可信直执行须显式选择。
- 外部服务与眼镜/手机/QQ真机验证单独列明，不能用离线测试代替。
