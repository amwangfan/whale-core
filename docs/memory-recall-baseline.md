# 记忆召回性能基线（issue #51）

测量日期：2026-11-02，硬件：生产 N100 小主机，Python 3.13。
复现：`PYTHONPATH=src python3 -m evals.memory_bench`（离线，合成记忆 +
确定性散列嵌入代理；真实网络嵌入每次调用成本约为本地散列的数百倍且计费，
缓存命中率形状一致）。

## 结论与决策（实测驱动）

1. **当前规模（百条级 curated 记忆）无瓶颈**：lexical 热召回 <5ms，hybrid
   <30ms。**不引入持久向量索引**——为架构而架构不值得。
2. 千条级：lexical ~30ms 足够；hybrid 热路径 56–140ms 可接受，前提是
   **嵌入缓存容量 ≥ 记忆规模**（默认 512 在千条以上会抖动失效，
   `texts_embedded` 实测随查询数线性增长）。
3. 万条级才出现真实瓶颈：lexical 170–340ms 开始可感知；hybrid 冷启动
   ~1.8s（本地散列），真实网络嵌入下冷启动 = 全量摘要多批 HTTP + 计费，
   且纯 Python 全量 cosine 扫描稳态也有 ~0.6s。**达到该规模时再实现按
   memory space / 模型版本 / 内容摘要增量更新的持久索引**，验收以本基线
   的同口径复测为准。
4. 廉价缓解已确认有效：缓存容量与记忆规模匹配即可把 hybrid 热路径压到
    lexical 同量级（千条 56ms）。

本基线不改变任何记忆读写、删除与召回语义；记忆空间隔离与词法兜底不变。
