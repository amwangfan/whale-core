# 记忆边界与手机经历

本文定义「谁的记忆能被谁看到」以及「手机上发生的事如何变成记忆」。实现：`memory/scopes.py`、`devices/privacy.py`、`devices/digest.py`；测试：`tests/test_memory_audience.py`、`tests/test_phone_memory.py`。

## 1. 以主人为中心的记忆受众

鲸鱼的主体是主人（部署者）。群聊和其他人的私聊是附属空间。

每次 Run 都有一个**受众（audience）**：

| 受众 | 典型来源 | 能读取 | 新记忆写入 |
| --- | --- | --- | --- |
| `owner` | 控制台、主人 QQ 私聊、手机、眼镜、任务、探索 | `owner` + `shared` + 所有 `group:*` | `owner`；鲸鱼自己的学习（knowledge/diary/skill）→ `shared` |
| `group:<渠道>:<群号>` | QQ 群 | 本群 + `shared` | 本群 |
| 其他人（如 `qq:1001`） | 其他人的私聊 | 此人 + `shared` | 此人 |
| 任意 | 鲸鱼在对话中自然形成的性格、口癖（`style`） | — | 始终 `shared` |

由此得到三条规则：

1. **群聊 → 主人，单向。** 主人会话可以用到群里学到的内容（召回时标注「来自群聊」，排序略低于主人自己的记忆）；群聊里的鲸鱼看不到主人的任何私人记忆，也看不到其他群。
2. **其他人的私聊完全隔离。** 从对方那里得到的事实、偏好、"知识"都只留在对方的作用域里。陌生人无法借私聊往共享知识里塞东西：对话提取不会产生 `knowledge`，一律降为对方作用域内的 `fact`。
3. **只有鲸鱼自己总结的性格与口癖跨边界。** 提取时可产生 `kind=style` 的条目：用第一人称描述鲸鱼自己的表达习惯，引用必须是**鲸鱼自己的原话**。对方要求鲸鱼扮演或改变身份的指令不会被当成习惯。`style` 不作为事实被召回，而是作为「你在相处中逐渐形成的习惯」注入每次对话的人格部分。

此外，非主人受众的 Run：

- 提示词中声明对话边界（这是群聊 / 与主人以外的人的私聊，不透露主人信息）；
- 不提供**仅主人**能力（`owner_only`）：Shell、创建/查看任务、所有设备操作、手机经历回想、客户端能力、QQ 主动发消息。模型即便臆造调用也会被拒绝。

过滤在 SQL 层执行（`scopes.sql_filter`），其他作用域的条目不会挤占召回名额。

## 2. 两种手机

| 角色 | 含义 | 默认判定 | 采集与记忆 |
| --- | --- | --- | --- |
| `agent` | 分配给鲸鱼使用的手机 | Root 构建（`app_flavor=root`） | 拥有全部能力；所有经历原样保留，不做隐私过滤；整理为鲸鱼自己的经历（「我在自己的手机上……」，subject=`self`） |
| `personal` | 主人日常使用的手机 | Daily 构建 | 默认全部记录，以下除外 |

角色可在控制台随时切换（`devices.set_role`）。

### 日常手机的隐私规则

参考 ScreenMemo 的采集策略（锁屏判定、系统界面/输入法/桌面/自动化辅助应用跳过、按应用选择、域名规则），把「不截屏」改为「不记忆」：

1. **系统隐私界面，永不保存**
   - 锁屏 / keyguard、FLAG_SECURE 窗口、密码输入框（事件 `extras` 中的 `locked`、`keyguard`、`secure`、`flag_secure`、`password`、`password_field`、`private_window`）；
   - 系统界面浮层（通知栏、快捷设置，含 MIUI/ColorOS/OriginOS/HarmonyOS 等变体）；
   - 输入法（键盘会显示正在输入的内容，包括密码）：搜狗、百度、讯飞、Gboard、SwiftKey 等；
   - 安全中心、权限弹窗、安装器、凭据管理、系统设置；
   - 密码管理器与验证器（Bitwarden、1Password、KeePass、Google Authenticator 等）。
2. **主人选择不记录的应用和网站**：应用包名列表；域名精确匹配或 `*.domain` 通配。
3. **手机自身标记为 `owner_sensitive` 的事件**（可关闭）。

其余内容正常记录，保存前对一次性验证码、银行卡号、身份证号做脱敏（可关闭）。

被过滤的事件在入口处只留一个**无内容墓碑**：事件 ID（用于去重和回执）和过滤原因代码，不保存摘要、应用包名或事件发生时间，控制台只显示各原因的计数。

### 从手机经历到长期记忆

调度器每 30 分钟（`devices.digest_interval_min`）执行一次「手机经历整理」，也可以在控制台手动触发：

1. 取每台设备水位线之后保留下来的事件；
2. 按时间切分片段（间隔超过 20 分钟即新片段），与 ScreenMemo 的片段总结思路一致；
3. fast 模型把每个片段概括为 1–2 条经历（episode），并只在有**逐字证据**时提取长期事实或偏好；
4. 写入 `owner` 受众，来源记录设备、时间段和事件 ID。手机记忆不会出现在群聊或其他人的私聊中。

主人还可以直接问「我刚才在手机上看的那个视频叫什么」：`phone.recall` 能力按关键词检索两台手机的近期经历（仅主人会话可用）。

## 3. 需要 whale-mobile 配合的部分

Core 侧的过滤是最终保障。更好的做法是手机在**采集时**就不碰这些界面：

- **采集侧跳过**：日常版在锁屏、FLAG_SECURE、密码框、系统界面、输入法和排除名单应用前台时不截屏、不 OCR，与 ScreenMemo 的做法一致；并在上报的 `extras` 中填写 `package`，以及能识别时的 `url`/`domain`、`secure`/`keyguard` 标记，这些都只是 Core 的输入。
- **策略同步（契约增量提案）**：新增下行消息 `device.policy {excluded_apps[], excluded_domains[], redact_secrets}`，由 Core 在 `hello_ack` 之后以及策略变更时下发，手机本地按此跳过采集。在此之前，排除名单只在 Core 生效：被排除应用的事件仍会上行，但到达即丢弃。
- **角色自报**：Root 构建默认视为鲸鱼专用手机；如果某台 Root 手机其实是主人日常用机，在控制台把角色改为 `personal` 即可，无需改 APK。


## 4. 群聊记忆空间（来自 #95）

主人可以把一个 QQ 群设为**记忆空间**（控制台「群聊」页，或 `groups.enable`）。实现：`groups/service.py`、`groups/analysis.py`；测试：`tests/test_groups.py`。

- **归档**：该群的每条消息（无论鲸鱼是否回复）都会写入本机 `group_messages` 表；也可以导入 QQ Chat Exporter 的 JSON 导出。归档只作为依据展示，**不会进入提示词**。
- **更新**（手动按钮，或可选的定时自动更新）：
  - 分词（安装 jieba 时用词性标注，否则退化为 n-gram），按 20 分钟间隔或 80 条切分话题段，计算段关键词与成员关键词；
  - 每位成员一份**群内画像**（`kind=person`）：与群内其他人相比更有区分度的口头禅（≥3 次、≥2 天）、常聊话题、典型反应，每一项都带消息 ID 作为依据；
  - **明确说过的喜好**（`kind=preference`）：只认第一人称、非假设、非转述、非敏感话题的原话；同一兴趣的新说法取代旧说法；超过 180 天的不再采纳。
- **作用域**：以上记忆都写入 `group:qq:<群号>`，主体为 `qq:<成员账号>`。因此本群的鲸鱼了解群友；主人的会话也能用上（单向规则）；别的群和其他人的私聊看不到。
- **控制**：
  - 成员**退出**（opt-out）后不再归档其发言，已归档的消息和关于他的画像、喜好全部删除；
  - **暂停**的空间不归档、不更新；
  - 删除空间时可选择一并遗忘相关记忆。
- **依据核验**：`memory.evidence` 只返回该记忆确实引用的消息；画像的依据必须是该成员本人的发言；原始消息已删除时如实返回「无法核验」，不会用摘要冒充原话。
